# 生成视频

## 何时用
用户给了一张图，要你让它动起来——「做成视频」「动起来」「加个镜头运动」。

**这套部署只做图生视频。** 后端装的是 I2V checkpoint，它的 pipeline 要求必须有图；`video_generate` 不传 `image_url` 会被直接拒掉，不会悄悄降级成文生视频。用户只给文字没给图时，问他要图，别硬调。

```
video_generate(prompt="...", image_url="...")
```

`image_url` 可以是 http(s) 链接，也可以是 `data:image/...;base64,...`。**聊天界面本身不收图片**——没有粘贴、没有拖放、没有上传按钮——所以图片要么是用户贴进来的链接，要么是你能用文件工具读到的本地文件转成 data URL。

提示词在这里描述的是**这张图要怎么动**：镜头怎么走、画面里什么在变，而不是重新描述图里已有的内容。

## 调用前先说一句
720p / 5 秒在这套硬件上是**几分钟**级别，不是几秒。调用会把整个回合占住，中途没有进度。所以：

1. 先用一句话告诉用户你要生成什么、大概要等多久；
2. 再调 `video_generate`；
3. 返回后报告结果路径，以及 `inference_time_s`（后端实测耗时，不是你的估计）。

## 提示词
Wan2.2 吃的是**画面描述**，不是指令。写镜头里能看见的东西：主体、动作、环境、光线、镜头运动。

- 好：`镜头缓慢右移，猫尾巴轻轻摆动，光柱里的尘埃缓缓浮动`
- 差：`生成一个关于猫的有趣视频`（没说怎么动）
- 也差：`一只三花猫在窗台上打盹`（图里已经有了，重复描述不会让它动）

`negative_prompt` 用来排掉不想要的（`模糊, 变形, 文字水印, 多余的手指`）。中英文都可以。

## 参数
默认 1280x720、16fps、5 秒。可调的：

- `duration`：秒，1–10。**时长直接乘耗时**，先问清楚再往上加。
- `aspect_ratio`：`16:9`（默认）/ `9:16`（竖屏）/ `1:1`
- `seed`：同一提示词要复现同一结果时传它
- `negative_prompt`

## 图片直接传给工具，不要先去"看"它
把 `image_url` 原样交给 `video_generate`，**不要先调 `vision_analyze` 或任何图像分析工具**。

那个工具把参数当**文件路径**用，一个 data URL 传进去会报
`[Errno 36] File name too long`，整轮就停在那里——实测如此。而且也没有必要：生成视频
不需要你先理解画面内容，提示词描述的是**怎么动**，不是画面里有什么。

用户若问"这图里是什么"，那是另一件事，用本地文件路径调 vision，不要用 data URL。

## 陷阱
- **别自己写 HTTP 调用。** 后端地址、表单格式、帧数要满足 4n+1、返回的是裸 mp4 字节——这些都在 provider 插件里处理了。你只管调 `video_generate`。
- **刚重启后会连不上。** 后端启动时要从 autumn 挂载读约 127 GB 权重，要几分钟，期间报 `connection_error`。这不是坏了，等一会再试，并如实告诉用户在等什么。
- **失败就照实说。** 返回 `success: false` 时把 `error` 原文给用户，不要重试三次再说，也不要编一个视频路径。
- **没有图就不要调。** 后端只有 I2V 权重，`video_generate` 少了 `image_url` 会返回 `unsupported_modality`。这时候要问用户要图，不要改写成文生视频糊弄过去。
